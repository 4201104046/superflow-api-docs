Reward Redemption & Points API

Tài liệu cho FE làm 2 tab Redemption và Point trong trang chi tiết campaign (design "Opella Reward · Admin v1.0"). Mỗi endpoint có body mẫu, response mẫu và bảng map từng cột trên UI sang field API. Response mẫu là dữ liệu minh họa, đúng shape thật.

Host devhttps://api-staging.superflow.vn
Base path/api/v1/reward/web
AuthAuthorization: Bearer <JWT>
Response wrapper{ success, result, error }
Ngày giờyyyy-MM-ddTHH:mm:ss (giờ local, không timezone)

Cách dùng chung cho mọi màn danh sách: gọi song song list-totalrow (lấy số trên tab và tổng để phân trang) và list-pageindex (lấy dữ liệu trang hiện tại) với cùng bộ filter. Khi đổi trang chỉ gọi lại list-pageindex.

to_date chỉ cần gửi ngày, API tự lấy tới 23:59:59. searchtext rỗng thì gửi "".

Vấn đề đang mở

Đã kiểm tra trên DB dev ngày 05/11/2026. Các mục này cần team DB/BE xử lý, FE làm tạm theo hướng dẫn bên trên.

  1. Bộ lọc nâng cao (Match all/any + New Rule) đang lỗiFunction dựng điều kiện lọc chưa có trên DB dev. Gửi filter_definition có rule thì list-pageindex trả [] mà không báo lỗi, còn list-totalrow trả lỗi. FE gửi null cho tới khi sửa xong.
  2. Chưa lọc theo campaignCả 2 màn nhận campaign_id nhưng SQL bỏ qua. Tab Redemption và Point của 1 campaign sẽ hiện dữ liệu của mọi campaign.
  3. Wallet transaction chưa lọc theo tenant3 API Point trả giao dịch của mọi tenant.
  4. Redemption trên dev chưa ra dữ liệu với tenant thậtTenant của người tham gia trên dev đang là 0, nên tenant_id=1 trả 0 dòng và get-by-id báo không tìm thấy. Đây là do dữ liệu dev.
  5. Thiếu field so với designRedemption: Province, Source, Issued code. Point: thông tin người tham gia, tên loại giao dịch, dấu ± của điểm, tên người tạo, số theo từng loại cho thẻ thống kê.
